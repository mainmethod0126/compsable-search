# 0.5.0 마이그레이션 노트

## 메타

- 대상 버전: `0.4.x -> 0.5.0`
- 마지막 갱신: `2026-03-04`
- 자동화 스크립트: `scripts/migrate-to-0.5.mjs`

## 1. 자동화(codemod) 사용법

### 1.1 자동 변환 규칙

- `selectorsProps -> selectors`
- `placeHolder -> placeholder`
- JSX `<ComposableSearch ...>` 오프닝 태그의 `onChange={...} -> onValueChange={...}`

안전성 기준:

- 문자열/주석/템플릿 리터럴 내부 텍스트는 치환하지 않는다.
- `<ComposableSearch ...>` 태그에 이미 `onValueChange`가 있으면 `onChange` 자동 치환을 스킵한다(중복 방지).

### 1.2 실행 방법

기본 모드는 `dry-run`(파일 미수정)이다.

```bash
node scripts/migrate-to-0.5.mjs --dry-run
```

실제 반영은 `--write`를 사용한다.

```bash
node scripts/migrate-to-0.5.mjs --write src
```

복수 경로도 가능하다.

```bash
node scripts/migrate-to-0.5.mjs --write src apps/web
```

### 1.3 옵션

| 옵션 | 설명 |
| --- | --- |
| `--dry-run` | 변경 미리보기(기본값) |
| `--write` | 실제 파일 수정 |
| `-h`, `--help` | 도움말 출력 |

### 1.4 출력 예시


## 2. 수동 점검 체크리스트

- [ ] `<ComposableSearch ...>` 사용처에서 `onChange`가 `onValueChange`로 전환되었는지 확인했다.
- [ ] `selectorsProps` 전달이 모두 `selectors`로 전환되었는지 확인했다.
- [ ] `placeHolder` 키가 모두 `placeholder`로 전환되었는지 확인했다.
- [ ] 동일 태그에 `onChange`와 `onValueChange`가 함께 존재하는 케이스를 수동 정리했다.
- [ ] spread props(`{...props}`)를 통해 전달되는 레거시 키가 남아있는지 확인했다.
- [ ] wrapper 컴포넌트(예: `MyComposableSearch`) 내부의 레거시 매핑을 점검했다.
- [ ] 타입 단에서 `ComposableSearchProps` 객체를 직접 조립하는 코드의 `onChange` 키를 수동 점검했다.
- [ ] 변경 후 `test/lint/build`를 실행해 회귀가 없는지 확인했다.

권장 검증 명령:

- `npm run test`
- `npm run lint`
- `npm run build`

## 3. 실패/엣지 케이스 및 대응

| 케이스 | 원인 | 대응 |
| --- | --- | --- |
| `onChange` + `onValueChange`가 같은 `<ComposableSearch>` 태그에 함께 있음 | 중복 치환 시 속성 충돌 위험 | codemod가 `onChange` 치환을 스킵한다. 수동으로 하나의 핸들러로 정리한다. |
| `onChange`가 wrapper 컴포넌트 props에 있음 | codemod는 `<ComposableSearch>` 태그를 안전 범위로 제한 | wrapper 컴포넌트 구현 파일에서 `onChange` 전달 경로를 수동으로 `onValueChange`로 전환한다. |
| `{...props}`로 전달되어 키 이름이 태그에 직접 보이지 않음 | 정적 텍스트 치환으로는 spread 내부 의미 추론이 어려움 | spread 원본 객체를 찾아 `selectorsProps/onChange/placeHolder`를 직접 치환한다. |
| 문자열/주석에 레거시 키가 남아 보임 | 의도적 비치환(코드 의미 보존) | 실행 코드가 아닌 경우 유지 가능. 가이드 문서라면 수동 수정한다. |
| 타입 객체(`const props: ComposableSearchProps = { ... }`) 내부 `onChange` 잔존 | 태그 문맥 없이 `onChange`를 일괄 변경하면 오탐 위험 | 해당 객체를 수동으로 점검하고 `onValueChange`로 전환한다. |
| 파싱 불가 JSX(닫히지 않은 태그 등) | 문법 오류 파일 | codemod 경고를 확인하고 먼저 파일 문법을 복구한 뒤 재실행한다. |

## 4. 권장 적용 순서

1. `--dry-run`으로 변경 예정 파일/치환 수를 확인한다.
2. `--write`로 실제 반영한다.
3. 수동 체크리스트를 따라 스킵/엣지 케이스를 정리한다.
4. 테스트/린트/빌드로 회귀를 확인한다.
