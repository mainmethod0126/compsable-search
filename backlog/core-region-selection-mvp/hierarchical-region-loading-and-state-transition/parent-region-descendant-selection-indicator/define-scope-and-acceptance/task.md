## 상태 모델 정의 (FR-023)

### 1) 컬럼별 상태 부여 기준
| 컬럼 | 상태 | 조건 |
| --- | --- | --- |
| 시/도 item | `has-descendant-selected` | 동일 시/도 하위에 `읍/면/동 상세`, `시/군/구 전체`, `시/도 전체` 중 하나라도 선택됨 |
| 시/군/구 item | `has-descendant-selected` | 동일 시/군/구 하위에 `읍/면/동 상세` 또는 `읍/면/동의 전체(예: 강남구 전체)`가 선택됨 |
| 시/군/구 전체 토글 | `is-selected` | `시/도 전체` 조건 자체가 선택됨 |
| 읍/면/동 체크박스 | `is-selected` | 해당 항목(상세/전체)이 직접 선택됨 |

### 2) 상태 우선순위와 조합
| 우선순위 | 상태 | 규칙 |
| --- | --- | --- |
| P1 | 직접 선택(`is-selected`) | 체크박스/토글 자체 선택 상태. 다른 간접 상태보다 우선 |
| P2 | 현재 포커스(`is-current`) | 버튼 기반 현재 탐색 위치 표시 |
| P3 | 하위 선택 존재(`has-descendant-selected`) | 간접 표시 상태. `is-current`와 동시 존재 가능 |
| P4 | 기본(`default`) | 위 상태 미적용 시 |

- `is-current`와 `has-descendant-selected`가 동시에 존재하면 `is-current` 시각을 우선하되, 다른 item과 비교 시 두 상태를 클래스 단위로 구분 가능해야 한다.
- `has-descendant-selected`는 파랑 계열을 유지하되 `is-current` 대비 밝은 배경/연한 보더로 구분한다.

### 3) 핵심 시나리오 매핑
| 시나리오 | 기대 상태 |
| --- | --- |
| `서울특별시 > 강남구 > 역삼동` 선택 | 시/도 `서울특별시`: `has-descendant-selected`, 시/군/구 `강남구`: `has-descendant-selected` |
| `서울특별시 > 강남구 전체` 선택 | 시/도 `서울특별시`: `has-descendant-selected`, 시/군/구 `강남구`: `has-descendant-selected` |
| `서울특별시 전체` 선택(시/군/구 전체 토글) | 시/도 `서울특별시`: `has-descendant-selected` |
| 마지막 하위 선택 해제 | 상위 `has-descendant-selected` 즉시 제거 |

### 4) 구현/검증 입력 조건
- [T-154]는 `selectionPolicy`에서 상위 하이라이팅 파생 규칙을 구현하고, `ComposableSearch` UI 클래스 반영을 유지한다.
- [T-155]는 상세/전체 선택 및 해제, `is-current` 동시 표시, 다중 선택 유지/해제 시나리오를 자동화 테스트로 고정한다.
