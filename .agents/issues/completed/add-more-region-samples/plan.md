## 문제 정의
### 현재 동작
- 데모 지역 데이터(`src/DemoService.ts`)가 소규모(시/도 2, 시/군/구 3, 읍/면/동 4)라 대량 데이터 상황의 UI/UX와 렌더링 특성을 검증하기 어렵다.

### 기대 동작
- 대량 지역 샘플(중간/대형 규모)에서도 지역 선택 UI가 깨지지 않고, 선택/토글 동작과 콜백 계약이 유지되어야 한다.
- 팀이 동일 조건에서 반복 검증할 수 있도록 재현 가능한 샘플 구성 방식이 필요하다.

### 재현 조건
- `App` 데모에서 지역 선택 패널을 열고 시/도, 시/군/구, 읍/면/동을 순차 선택한다.
- 다수 항목이 있는 리스트에서 스크롤/선택/해제/전체 선택 토글을 반복한다.
- 모바일 폭(<=768px)과 데스크톱 폭(>=1024px) 모두 확인한다.

### 영향 범위
- `src/DemoService.ts`(샘플 데이터 소스)
- `src/App.tsx`(데모 진입 및 시나리오 선택 UI)
- `src/components/ComposableSearch.css`(대량 리스트 가독성/스크롤 UX)
- `src/components/RegionDetailPanel.tsx`, `src/components/SelectableRegionColumn.tsx`, `src/components/CheckableRegionColumn.tsx`(대량 항목 렌더링 경로)
- 테스트(`src/components/ComposableSearch.test.tsx`, 데모/계약 테스트)

## 성공 기준 / 비목표
### 성공 기준
- [ ] 재현 가능한 샘플 프로파일 3종(`small`, `medium`, `large`)이 정의되고, 데모에서 프로파일 전환이 가능하다.
- [ ] `large` 프로파일에서 지역 패널 사용 시 레이아웃 깨짐(가로 overflow, 클릭 불가, 선택 상태 불일치)이 발생하지 않는다.
- [ ] 기존 region 콜백 계약(`onClick`, `onChange`, `onSelectedEupmyeondong`)이 대량 샘플에서도 회귀 없이 유지된다.
- [ ] 자동 테스트에 대량 샘플 시나리오가 추가되고 CI에서 안정적으로 통과한다.

### 비목표
- 실제 행정구역 정합성이 100%인 실데이터 구축
- 대규모 가상 스크롤(virtualization) 프레임워크 도입
- API 서버/DB 연동으로 데이터 소스 전환

## 해결 대안 비교
| 대안 | 핵심 아이디어 | 장점 | 리스크 | 구현/검증 비용 |
| --- | --- | --- | --- | --- |

| B | 결정적(Deterministic) 지역 샘플 생성기 + 프로파일(`small/medium/large`) 도입 | 데이터 확장/축소가 쉬워 재현성과 테스트성이 높음 | 생성 규칙 설계 필요, 초기 구조화 비용 존재 | Medium |
| C | 테스트 코드에서만 대량 fixture 사용하고 데모는 유지 | 테스트 속도 개선에 집중 가능 | 실제 데모 UX 검토 불가, 이슈 목적(가늠/시각 확인) 미충족 | Low |

## 권장 해결안
- 선택 대안: `B`
- 선택 근거:
  - 이슈 목표가 “UI/UX 가늠 + 렌더링 문제 확인”이므로 데모에서 즉시 전환 가능한 샘플 프로파일이 필요하다.
  - 결정적 생성기를 쓰면 테스트와 수동 검증이 동일 데이터 조건을 공유할 수 있어 재현성이 높다.
- 기각한 대안과 사유:
  - `A`: 단기 확인은 쉽지만 장기적으로 데이터 유지비가 크고 확장성 낮음
  - `C`: 자동 검증만 가능하고 실제 UI 관찰 목적을 충족하지 못함

## 테스트 및 검증 계획
### Unit
- 샘플 생성 유틸에서 `region.code` 유일성, 부모-자식 코드 규칙, 프로파일별 수량 검증
- 프로파일 전환 함수가 기대한 데이터셋을 반환하는지 검증

### Integration
- `ComposableSearch`에서 large 데이터로 패널 열기/항목 선택/선택 해제/전체 선택 시 상태 및 콜백 정상 동작 검증
- 모바일 브레이크포인트에서 컬럼 구조가 1열 전환되어도 상호작용이 유지되는지 검증

### Regression
- 기존 `ComposableSearch.test.tsx` 주요 계약 테스트 전수 통과
- `App` 콜백 이벤트 로그 동작 회귀 여부 확인

### 필요 시 추가
- 성능: 패널 오픈/첫 선택 처리 시간 계측(프로파일별 baseline 기록)
- 보안: 외부 입력 경로가 없으므로 신규 보안 리스크는 낮음(정적/생성 데이터만 사용)

## 배포 / 롤백 / 운영 관측
### 배포 전략
- 1개 PR로 배포하되, 기본 프로파일은 `small` 유지 후 검증 환경에서 `medium/large`를 선택 가능하게 한다.

### 롤백 전략
- 트리거: 대량 프로파일에서 선택 불가, 콜백 누락, 테스트 불안정 발생
- 절차: 프로파일 전환 UI와 생성 유틸 변경 커밋 revert 후 기존 `small` 정적 데이터로 복귀

### 운영 관측
- 핵심 지표: 패널 오픈 시간, 항목 선택 후 UI 반영 시간, 테스트 실행 시간 증가폭
- 로그/트레이싱 포인트: 프로파일명, 항목 수, 콜백 호출 횟수
- 알람 조건: CI 테스트 시간 급증/플레이크 증가, 핵심 시나리오 실패
