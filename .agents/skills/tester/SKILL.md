# 테스터 스킬

## 진입 정책을 적용한다

- 모든 처리 요청은 `project-commander`를 통해 시작하는 것을 기본 규칙으로 둔다.
- 이 스킬은 `project-commander`가 배정한 작업을 우선 처리한다.
- 사용자가 이 스킬을 직접 지정하면 즉시 처리하되, 필요 시 목표/범위/완료 조건을 먼저 확인한다.

## 다음 워크플로를 수행한다

1. 요청의 테스트 목표(무엇을 검증할지, 언제까지, 어떤 산출물인지)를 식별한다.
2. PRD와 변경 파일을 읽고 검증 범위를 정의한다.
3. 요구사항 ID(`FR-*`, `NFR-*`, `AC-*`)를 테스트 케이스로 매핑한다.
4. 자동 검증 명령과 수동 검증 시나리오를 분리해 실행한다.
5. 실패 원인, 회귀 위험, 배포 차단 이슈를 문서화한다.
6. 테스트 리포트와 즉시 실행 가능한 다음 작업을 제시한다.

다음 파일을 먼저 읽는다:
- `PRD.md`
- `PRD.en.md`
- `package.json`
- 관련 계획 파일(`.agents/plans/` 하위)
- 변경 영향이 있는 `src/` 하위 파일

필요하면 다음 참조 파일을 읽는다:
- `references/test-plan-template.md`
- `references/regression-checklist.md`
- `references/test-report-template.md`

## 테스트 설계 규칙을 적용한다

- 테스트 케이스는 요구사항 ID와 추적 가능하게 연결한다.
- 우선순위는 `Must/Should/Could`를 `P0/P1/P2`로 매핑한다.
- 기능/비기능/회귀 테스트를 분리해 설계한다.
- 경계값, 오류 처리, 예외 시나리오를 기본 포함한다.
- 재현 절차와 기대 결과를 모호하지 않게 작성한다.

## 검증 실행 규칙을 적용한다

- `package.json`에 정의된 검증 명령(`lint`, `build`, `test`)을 우선 사용한다.
- `test` 스크립트가 없으면 수동 검증 절차를 명시적으로 작성한다.
- 실패가 발생하면 원인 가설, 재현 명령, 임시 완화책을 함께 기록한다.
- 배포 차단 이슈는 `Release Blocker`로 분리한다.

## 저장소 제약사항을 강제한다

- 공개 React 컴포넌트 라이브러리(npm 배포 기준) 관점으로 검증 범위를 정한다.
- 외부 의존성 추가가 필요한 테스트는 필요성/대안/충돌 위험을 함께 기록한다.
- 전역 부작용(CSS 오염, 런타임 글로벌 수정, 강제 폴리필) 위험 항목을 점검한다.

## 산출물 형식을 고정한다

- 테스트 계획은 `references/test-plan-template.md`를 사용한다.
- 테스트 리포트는 `references/test-report-template.md`를 사용한다.
- 신규 문서는 `.agents/tests/<topic>-<yyyymmdd>.md` 형식으로 저장한다.

## 결과 체크리스트

- 요구사항 ID와 테스트 케이스 매핑 표
- 자동/수동 검증 결과
- 실패 항목의 원인 가설과 재현 절차
- 회귀 위험 및 Release Blocker
- 즉시 수행 가능한 다음 작업(Top 3)
