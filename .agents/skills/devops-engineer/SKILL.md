# 데브옵스 엔지니어 스킬

## 진입 정책을 적용한다

- 모든 처리 요청은 `project-commander`를 통해 시작하는 것을 기본 규칙으로 둔다.
- 이 스킬은 `project-commander`가 배정한 작업을 우선 처리한다.
- 사용자가 이 스킬을 직접 지정하면 즉시 처리하되, 필요 시 목표/범위/완료 조건을 먼저 확인한다.

## 다음 워크플로를 수행한다

1. 요청을 운영 과제로 재정의한다(파이프라인 개선, 배포 전략, 장애 대응, 비용/안정성 최적화).
2. 저장소와 배포 관련 파일을 읽고 현재 운영 상태를 파악한다.
3. 목표 상태와 제약사항(가용성, 배포 빈도, 복구 시간)을 정리한다.
4. 실행 가능한 변경안과 검증 계획을 제시한다.
5. 배포/운영 리스크와 롤백 절차를 포함한 결과 문서를 작성한다.

다음 파일을 먼저 읽는다:
- `package.json`
- `PRD.md`
- `PRD.en.md`
- `.github/workflows/` 하위 CI 파일(존재 시)
- `Dockerfile*`, `docker-compose*.yml`(존재 시)
- 배포/인프라 스크립트 및 설정 파일(존재 시)

필요하면 다음 참조 파일을 읽는다:
- `references/cicd-checklist.md`
- `references/deployment-strategy-template.md`
- `references/operations-runbook-template.md`

## CI/CD 설계 규칙을 적용한다

- 최소 품질 게이트로 `lint`, `build`, `test`를 파이프라인에 포함한다.
- 실패 시 즉시 중단(fail fast)하고 실패 단계와 원인을 기록한다.
- 아티팩트는 버전/커밋 기준으로 추적 가능하게 관리한다.
- 캐시 전략은 빌드 시간 단축과 재현성 균형을 유지한다.

## 배포 전략 규칙을 적용한다

- 사용자 요청 없이 특정 클라우드/플랫폼을 가정하지 않는다.
- `Rolling`, `Blue/Green`, `Canary` 중 목표와 리스크에 맞는 전략을 선택한다.
- 각 전략에 대해 배포 성공 기준, 관측 지표, 롤백 트리거를 명시한다.
- 마이그레이션/데이터 변경이 있으면 선행 검증과 복구 절차를 포함한다.

## 운영 안정성 규칙을 적용한다

- 로그/메트릭/알람 기반 관측성을 배포 계획에 포함한다.
- 장애 대응 문서에는 탐지, 완화, 복구, 사후 분석 단계를 포함한다.
- SLO/SLI가 있다면 배포 판단 기준에 반영한다.
- 운영 변경은 재현 가능한 명령과 책임 주체를 함께 기록한다.

## 저장소 제약사항을 강제한다

- 공개 React 컴포넌트 라이브러리 배포(npm 기준) 관점으로 판단한다.
- 외부 의존성 추가 시 필요성, 대안, 충돌 위험을 함께 기록한다.
- API 단순성, 예측 가능성, 하위 호환성을 유지한다.
- 전역 부작용(CSS 누수, 런타임 글로벌 수정, 강제 폴리필) 유발 가능성을 점검한다.

## 산출물 형식을 고정한다

- CI/CD 개선안은 `references/deployment-strategy-template.md`를 기반으로 작성한다.
- 운영 대응 문서는 `references/operations-runbook-template.md`를 기반으로 작성한다.
- 신규 문서는 `.agents/ops/<topic>-<yyyymmdd>.md` 형식으로 저장한다.

## 결과 체크리스트

- 파이프라인 단계별 게이트와 실패 기준이 명확한가
- 배포 전략과 롤백 기준이 문서화됐는가
- 운영 관측/알람/장애 대응 절차가 포함됐는가
- 릴리스 차단 이슈와 즉시 수행 가능한 다음 작업(Top 3)이 정의됐는가
