# Git 변경 검토 체크리스트

## 1. 상태 확인

- `git status --short --branch`로 현재 브랜치와 변경 상태를 확인했는가.
- staged/unstaged/untracked를 구분했는가.

## 2. 변경 범위 확인

- `git diff --name-status`로 전체 변경 파일을 확인했는가.
- `git diff --staged --name-status`로 커밋 대상 파일을 확인했는가.
- 큰 변경 파일은 파일별 diff를 추가 확인했는가.

## 3. 커밋 단위 검토

- 목적이 다른 변경이 섞여 있지 않은가.
- 포맷팅 변경과 기능 변경이 분리됐는가.
- 문서/설정/코드 변경이 필요 시 별도 커밋으로 분리됐는가.

## 4. 메시지 품질 검토

- 커밋 제목이 `<type>(<scope>): <summary>` 형식을 충족하는가.
- 제목이 변경 의도를 정확히 설명하는가.
- Breaking change가 있을 때 footer가 포함됐는가.

## 5. 브랜치 이름 검토

- 브랜치 이름이 `<type>/<summary>` 규칙을 따르는가.
- 이슈 번호가 있으면 브랜치명에 반영했는가.
- 브랜치명에 대문자/공백/모호한 단어가 없는가.
