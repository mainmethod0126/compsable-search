# 퍼블리셔 스킬

## 진입 정책을 적용한다

- 모든 처리 요청은 `project-commander`를 통해 시작하는 것을 기본 규칙으로 둔다.
- 이 스킬은 `project-commander`가 배정한 작업을 우선 처리한다.
- 사용자가 이 스킬을 직접 지정하면 즉시 처리하되, 필요 시 목표/범위/완료 조건을 먼저 확인한다.

## 다음 워크플로를 수행한다

1. 요청에서 배포 대상(`npm package` 또는 `web demo`)과 목표 환경을 식별한다.
2. 배포 전 상태(버전, 아티팩트, 차단 요인)를 점검한다.
3. 대상별 체크리스트에 따라 검증 명령을 실행하고 결과를 기록한다.
4. 배포 리포트를 작성하고 즉시 후속 작업을 제시한다.

다음 파일을 먼저 읽는다:
- `package.json`
- `PRD.md`
- `PRD.en.md`
- `vite.config.ts`
- 배포 영향이 있는 경우 `src/` 하위 관련 파일

필요하면 다음 참조 파일을 읽는다:
- `references/publish-checklist.md`
- `references/npm-readiness-checklist.md`
- `references/publish-report-template.md`

## 공통 배포 규칙을 적용한다

- 배포 전 최소 검증으로 `npm run lint`, `npm run build`를 수행한다.
- 명령 실패 시 실패 로그 요약, 원인 가설, 복구 작업을 함께 기록한다.
- 사용자 요청 없이 배포 대상 인프라를 가정하지 않는다.
- 배포 결과는 재현 가능한 명령/아티팩트 경로 중심으로 보고한다.

## npm 패키지 배포 규칙을 적용한다

- `package.json`의 `private`가 `true`이면 배포 차단으로 분류한다.
- 패키지 이름, 버전(SemVer), 엔트리(`exports`/`main`/`types`), `files` 포함 범위를 점검한다.
- 실제 퍼블리시 전 `npm pack --dry-run`으로 포함 파일을 확인한다.
- 필요한 경우 `npm pack` 결과물(`*.tgz`)을 검증 아티팩트로 기록한다.

## 데모 웹 배포 규칙을 적용한다

- `npm run build` 결과인 `dist/`를 기본 배포 아티팩트로 사용한다.
- 정적 리소스 경로와 base 설정(`vite.config.ts`)을 검토한다.
- 배포 제공자(GitHub Pages, Netlify, Vercel 등)는 사용자가 명시한 경우에만 맞춤 절차를 적용한다.

## 저장소 제약사항을 강제한다

- 결과는 공개 React 컴포넌트 라이브러리 배포 관점(npm 기준)으로 정리한다.
- 외부 의존성 추가가 필요하면 필요성, 대안, 충돌 위험을 함께 명시한다.
- 전역 부작용(CSS 오염, 런타임 글로벌 수정, 강제 폴리필) 위험을 배포 체크 항목에 포함한다.

## 산출물 형식을 고정한다

- 배포 리포트는 `references/publish-report-template.md`를 기본 템플릿으로 사용한다.
- 신규 리포트 파일은 `.agents/releases/<target>-<yyyymmdd>.md` 형식으로 생성한다.
- 기존 리포트 업데이트 시 섹션 구조를 유지하고 변경된 항목만 수정한다.

## 결과 체크리스트

- 배포 대상과 버전(또는 커밋/태그 대체 식별자)
- 실행 명령과 성공/실패 결과
- 생성 아티팩트 경로(`dist/`, `*.tgz` 등)
- 배포 차단 이슈 및 해소 조건
- 즉시 수행 가능한 다음 작업(Top 3)
