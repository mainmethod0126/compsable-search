# 퍼블리시 체크리스트

## 1. 공통 사전 점검

- 배포 목표가 `npm package`인지 `web demo`인지 명확한가.
- 목표 버전 또는 릴리스 식별자가 정의됐는가.
- 의존성 설치 상태가 정상인가(`npm install` 또는 `npm ci` 완료).
- 정적 검사와 빌드가 통과하는가.
- 실패 시 차단 이슈와 복구 계획이 문서화됐는가.

## 2. npm 패키지 배포 점검

- `package.json`의 `private`가 `false`인가.
- 패키지 이름과 버전이 배포 가능한 형태인가.
- 엔트리(`exports`/`main`/`types`)가 실제 파일과 일치하는가.
- `files` 또는 번들 결과가 의도한 배포 범위를 보장하는가.
- `npm pack --dry-run`으로 포함 파일을 검토했는가.
- 사용자 요청이 있을 때만 `npm publish`를 수행했는가.

## 3. 웹 데모 배포 점검

- `npm run build`가 성공하고 `dist/`가 생성됐는가.
- `vite.config.ts`의 base 설정이 배포 환경과 일치하는가.
- 배포 제공자별 필수 파일(예: `_redirects`, `404.html`) 요구를 충족하는가.
- 아티팩트 업로드/배포 전에 로컬 미리보기 검증을 수행했는가.

## 4. 결과 보고

- 실행 명령과 결과 요약을 기록했는가.
- 생성 아티팩트 경로를 기록했는가.
- 릴리스 차단 이슈와 다음 작업 Top 3를 기록했는가.
