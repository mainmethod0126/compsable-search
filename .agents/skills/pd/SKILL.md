# 제품 프로듀서 스킬

## 다음 워크플로를 수행한다

1. 요청에서 목표, 대상 사용자, 릴리스 범위를 식별한다.
2. 문서 작성 전에 저장소 컨텍스트를 필요한 범위로만 확인한다.
3. 제약사항을 추출하고 명시적인 PRD 요구사항으로 변환한다.
4. 구현 작업 제안보다 PRD 작성 및 갱신을 우선한다.
5. 한국어/영어 PRD 문서를 동일한 변경 세트에서 동기화한다.

다음 파일을 먼저 읽는다:
- `AGENTS.md`
- `PRD.md`
- `PRD.en.md`
- `src/` 하위의 관련 소스 파일

파일이 없거나 비어 있으면 다음 순서로 처리한다:
- `PRD.md`가 없으면 기본 구조(13개 섹션)로 생성한다.
- `PRD.en.md`가 없으면 `PRD.md`와 동일 범위를 영어로 생성한다.
- 둘 중 하나가 비어 있으면 내용이 있는 파일을 기준으로 동기화한다.

필요하면 다음 참조 파일을 읽는다:
- `references/prd-template.md`
- `references/prd-sync-checklist.md`

## 저장소 제약사항을 강제한다

- 제품을 재사용 가능한 공개 React 컴포넌트 라이브러리로 전제한다.
- 요구사항을 npm 배포 가능 상태 기준으로 설계한다.
- 외부 의존성은 최소화하고 의존성 변경 시 근거를 명시한다.
- API는 간결하고 예측 가능하며 도입이 쉬워야 한다.
- 구현 요구사항에는 구체적인 영어 JSDoc 작성을 포함한다.
- 전역 부작용, CSS 누수, 강제 폴리필 등 사용자 환경 충돌 요소를 방지한다.

## 다음 PRD 구조를 사용한다

1. 제품 요약
2. 문제 정의
3. 대상 사용자 및 핵심 사용 사례
4. 목표
5. 비목표
6. 이번 릴리스 범위
7. 기능 요구사항
8. 컴포넌트 및 API 요구사항
9. 비기능 요구사항
10. 수용 기준
11. QA 및 검증 계획
12. 릴리스 및 버저닝 계획
13. 리스크 및 오픈 이슈

## 산출물 템플릿을 고정한다

- 신규 PRD 초안은 `references/prd-template.md`를 기반으로 작성한다.
- 기존 PRD 업데이트 시 섹션 구조를 유지하고 변경된 항목만 최소 수정한다.
- `PRD.md`와 `PRD.en.md` 동기화 점검은 `references/prd-sync-checklist.md`를 따른다.

## 요구사항은 다음 방식으로 작성한다

- 모든 요구사항은 테스트 가능하고 모호하지 않게 작성한다.
- 정성적 표현보다 측정 가능한 표현을 우선한다.
- 우선순위 라벨 `Must`, `Should`, `Could`를 부여한다.
- 요구사항 ID를 사용해 추적 가능하게 관리한다. 권장 형식: `FR-001`, `NFR-001`, `AC-001`.
- 주요 요구사항마다 수용 기준을 연결한다.
- 정보가 부족하면 가정을 명시한다.
- 미결정 사항은 오픈 이슈로 정리한다.
- PRD는 동일한 입력과 제약에서 다른 구현자가 작업해도 동일한 제품으로 수렴할 수준으로 구체화한다.
- 각 핵심 기능마다 사용자 흐름, 상태 변화, 입력/출력, 오류 처리, 예외 케이스, 완료 조건을 포함한다.
- 컴포넌트/API 요구사항에는 props 시그니처, 타입 제약, 기본값, 이벤트 계약, 접근성 요구사항을 명시한다.
- 비기능 요구사항에는 성능/번들 크기/호환성/테스트 범위를 가능한 한 수치 기준으로 명시한다.

## PRD 파일을 동기화한다

- `PRD.md`와 `PRD.en.md`의 섹션 순서와 범위를 일치시킨다.
- 동일한 요구사항 변경은 두 파일에 한 번의 업데이트로 반영한다.
- 한 파일이 비어 있으면 다른 파일 기준으로 초기화한다.
- 두 문서가 동등해질 때까지 번역 공백을 명시적으로 표시한다.

동기화 완료 전에 다음을 검증한다:
- 두 문서의 섹션 제목과 순서가 1:1로 일치한다.
- 요구사항 ID, 우선순위(`Must`/`Should`/`Could`), 수용 기준 매핑이 동일하다.
- 컴포넌트/API 이름, 파라미터, 제약사항이 의미 단위로 동일하다.

## PRD 업데이트 결과 체크리스트

- 변경된 섹션
- 신규 또는 수정된 요구사항
- 추가 또는 수정된 수용 기준
- 제품 의사결정이 필요한 오픈 이슈
- 다음 구현 가능 작업
- 문서 동기화 검증 결과(섹션/요구사항/수용 기준 일치 여부)
- 재현 가능성 검증 결과(해당 PRD만으로 동일 제품 구현 가능 여부와 부족 정보)
