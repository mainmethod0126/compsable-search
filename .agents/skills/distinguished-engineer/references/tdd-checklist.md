# TDD 점검 체크리스트

## 사용 방법

1. 태스크를 테스트 가능한 수용 기준으로 분해한다.
2. 각 수용 기준마다 실패 테스트(Red)를 먼저 작성한다.
3. 최소 구현(Green)으로 테스트를 통과시킨다.
4. 구조 개선(Refactor) 후 전체 테스트를 재실행한다.

## Red 단계

- 요구사항을 재현하는 테스트가 먼저 존재하는가?
- 테스트가 현재 코드에서 실제로 실패하는가?
- 실패 원인이 요구사항과 직접 연결되는가?

금지:
- 테스트 없이 프로덕션 코드를 먼저 작성함
- 실패 원인이 환경/설정 문제인데도 기능 실패로 오인함

## Green 단계

- 실패 테스트를 통과시키는 최소 코드만 추가했는가?
- 불필요한 추상화/최적화를 도입하지 않았는가?
- 변경 범위가 태스크 경계를 넘지 않았는가?

금지:
- “미래 대비” 명목으로 과도한 범위를 함께 구현함
- 테스트를 억지로 통과시키기 위해 의미 없는 하드코딩을 사용함

## Refactor 단계

- 중복 제거, 책임 분리, 의존성 분리를 적용했는가?
- SOLID 위반 냄새가 줄었는가?
- 리팩토링 후 테스트가 모두 통과하는가?

금지:
- 테스트를 깨뜨린 상태로 리팩토링을 종료함
- 동작 변경을 리팩토링으로 위장함

## 완료 조건

- 새로 추가/수정한 테스트가 모두 통과함
- 관련 회귀 테스트가 통과함
- 변경 의도와 테스트 결과를 작업 로그에 남김

## 결과 기록 템플릿

```md
### TDD 실행 로그
- Red: [추가한 테스트], [실패 확인 결과]
- Green: [최소 구현 요약], [통과 확인 결과]
- Refactor: [구조 개선 내용], [전체 테스트 결과]
```
