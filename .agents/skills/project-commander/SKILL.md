# 프로젝트 총지휘자 스킬

## 진입 게이트를 적용한다

- 모든 처리 요청은 기본적으로 이 스킬에서 먼저 트리아지한다.
- 다른 스킬 실행 전 우선순위, 담당, 완료 조건을 확정한다.
- 사용자가 특정 실행 스킬을 직접 지정해도 가능하면 최소 트리아지 결과를 먼저 남긴다.

## 다음 워크플로를 수행한다

1. 요청을 실행 가능한 문제 정의로 변환한다.
2. 현재 맥락(요구사항, 계획, 변경 상태, 리스크)을 빠르게 수집한다.
3. 작업을 분해하고 우선순위와 차단 관계를 결정한다.
4. 라우팅 기준에 따라 담당 에이전트를 배정한다.
5. 각 에이전트에게 전달할 지시 패킷(목표, 범위, 완료 조건, 검증)을 작성한다.
6. 병렬 실행 가능 항목과 순차 실행 항목을 구분한다.
7. 통합 일정과 추적 포인트를 포함한 지휘 결과를 출력한다.

다음 파일을 먼저 읽는다:
- `PRD.md`
- `PRD.en.md`
- `.agents/plans/` 하위 계획 문서
- 관련 소스 파일(`src/` 하위)
- 작업 유형에 따라 관련 설정 파일

필요하면 다음 참조 파일을 읽는다:
- `references/agent-routing-matrix.md`
- `references/intake-triage-checklist.md`
- `references/dispatch-plan-template.md`

## 트리아지 규칙을 적용한다

- 사용자 가치, 리스크, 긴급도를 기준으로 `P0/P1/P2` 우선순위를 부여한다.
- 해결 불가능한 막힘은 조기 식별해 `Blocker`로 분리한다.
- 정의되지 않은 요구사항은 즉시 질문 항목으로 분리한다.
- 작업이 크면 실행 가능한 최소 단위로 분해한다.

## 에이전트 배정 규칙을 적용한다

- 도메인 적합성, 선행 의존성, 검증 난이도를 함께 고려해 담당을 정한다.
- 하나의 작업에 여러 에이전트가 필요하면 주 담당 1명과 협업 순서를 명시한다.
- 라우팅 기준은 `references/agent-routing-matrix.md`를 기본으로 사용한다.
- 기존 에이전트로 처리 가능한 문제는 새 에이전트를 만들지 않는다.

## 지시 패킷 규칙을 적용한다

- 각 지시에는 목적, 입력 자료, 산출물, 완료 조건, 검증 방법을 포함한다.
- 파일 경로와 변경 범위를 가능한 구체적으로 지정한다.
- 완료 후 보고 형식을 미리 고정한다(무엇을, 어디에, 어떤 근거로 보고할지).

## 산출물 형식을 고정한다

- 지휘 결과는 `references/dispatch-plan-template.md`를 기본 템플릿으로 작성한다.
- 신규 지휘 문서는 `.agents/dispatch/<topic>-<yyyymmdd>.md` 형식으로 저장한다.
- 기존 지휘 문서 업데이트 시 섹션 구조를 유지하고 변경 항목만 수정한다.

## 결과 체크리스트

- 우선순위와 Blocker가 명확한가
- 각 작업의 담당 에이전트가 적절한가
- 선행 관계와 병렬 가능 항목이 정의됐는가
- 완료 조건과 검증 방법이 각 지시에 포함됐는가
- 즉시 시작 가능한 다음 작업(Top 3)이 제시됐는가
