# PRD 동기화 체크리스트

## 1. 범위 정합성

- [ ] PRD 목표와 현재 구현 범위가 일치한다.
- [ ] 제외 범위(Out of Scope) 섹션이 최신 상태다.
- [ ] 사용자 스토리/요구사항 ID가 코드 변경과 매핑된다.

## 2. 요구사항 정합성

- [ ] 기능 요구사항(FR)별 구현 상태가 확인된다.
- [ ] 비기능 요구사항(성능/보안/접근성) 충족 여부가 검증된다.
- [ ] 수용 기준이 테스트 케이스와 연결된다.

## 3. 기술 문서 정합성

- [ ] 아키텍처 문서(ADR/설계서)와 PRD 의사결정이 일치한다.
- [ ] API/스키마 변경 사항이 PRD에 반영된다.
- [ ] 기술 부채 및 제약 사항이 최신화된다.

## 4. 일정 및 릴리스 정합성

- [ ] 마일스톤 날짜가 절대 날짜 `YYYY-MM-DD` 형식으로 업데이트된다.
- [ ] 릴리스 범위가 실제 배포 계획과 일치한다.
- [ ] 출시 판정 기준(Go/No-Go)이 명확하다.

## 5. 품질 및 검증 정합성

- [ ] 테스트 결과(단위/통합/E2E)가 PRD 성공 기준과 연결된다.
- [ ] 알려진 리스크와 대응 계획이 최신 상태다.
- [ ] 모니터링 지표와 성공 KPI 정의가 일치한다.

## 6. 커뮤니케이션 정합성

- [ ] 의사결정 로그가 최신이다.
- [ ] 오픈 이슈에 담당자와 기한이 포함된다.
- [ ] 이해관계자 승인 상태가 명확하다.
