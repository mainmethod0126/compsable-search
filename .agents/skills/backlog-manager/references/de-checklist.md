# Distinguished Engineer 관점 점검 체크리스트

## 1. 아키텍처/경계

- 변경 영향 범위(서비스, 모듈, API 경계)를 명시한다.
- 인터페이스 호환성(하위 호환, 버전 전략)을 명시한다.
- 장애 격리 전략(서킷브레이커, 타임아웃, 재시도)을 고려한다.

## 2. 데이터/정합성

- 스키마 변경 여부와 마이그레이션/롤백 계획을 분리해 작성한다.
- 데이터 품질 검증(중복, 누락, 정합성) Task를 포함한다.
- 백필/리인덱싱/캐시 무효화가 필요하면 별도 Task로 분해한다.

## 3. 성능/비용

- 성능 목표(p95, p99, 처리량)를 수치로 명시한다.
- 부하 테스트 또는 성능 회귀 검증 Task를 포함한다.
- 인프라 비용 증가 가능성과 상한을 점검한다.

## 4. 보안/규제

- 인증/인가 변경사항을 식별하고 테스트 Task를 포함한다.
- 개인정보/민감정보 저장·전송 경로를 점검한다.
- 감사 로그, 키 관리, 비밀 관리 Task를 포함한다.

## 5. 운영/관측 가능성

- 메트릭, 로그, 트레이스 계측 Task를 포함한다.
- 알람 기준과 온콜 대응 흐름을 정의한다.
- 장애 대응 런북과 롤백 플랜을 문서화한다.

## 6. 품질/릴리스

- 단위/통합/E2E 테스트 전략을 각각 확인한다.
- 기능 플래그, 점진 배포, 카나리/블루그린 전략을 검토한다.
- 릴리스 후 검증(Post-release validation) Task를 포함한다.

## 7. 팀 실행 가능성

- Task가 역할 단위로 명확히 분리되어 있는지 확인한다.
- 선행조건과 병렬 가능 작업이 명시되어 있는지 확인한다.
- 교차팀 의존성(데이터/보안/인프라/법무)을 명시한다.

## 8. UI/UX 선행 게이트(해당 시)

- UI/UX 관련 Feature마다 `UI/UX 선행 UserStory`를 포함한다.
- UI/UX 선행 UserStory에 시안/프로토타입/사용성 검증/디자인 핸드오프 Task를 포함한다.
- 기능 구현 Task의 선행조건에 `디자인 확정/핸드오프` Task ID를 연결한다.
- 디자인 산출물에 로딩/빈 상태/오류 상태와 접근성 기준(키보드, 대비, 스크린리더)을 포함한다.
